# GitHub Cumulative Intelligence

Use this skill before proposing or drafting a new PR in this stack.

1. Refresh canonical `GitHubMemoryIndex` snapshots with the existing #447 `state=all` snapshotter.
2. Include every relevant repository index. Do not discard merged or closed-not-merged PRs.
3. Compile `omega_capability_os_t.github_cumulative_intelligence_cli`.
4. Read the minimal reuse coalition, relevant PR genomes, lineage neighborhood and negative-memory hits.
5. Run the leakage-controlled `github_retrieval_arena` policy when historical ancestry/reuse candidates matter. The current `hybrid_rrf` policy is **probationary**, not canonical truth: its v0.2 frozen baseline improved historical Recall@8 in this repository, but retrospective success is not prospective or cross-repository validation.
6. Treat retrieval rankings as an inspection queue only. Progressively inspect exact candidate heads/files/tests before reusing implementation; a high rank never proves semantic equivalence or implementation compatibility.
7. Reuse/compose/extend before creating. Create only declared residual outputs.
8. Keep provenance to repository, PR and exact head SHA.
9. Treat `MERGED != M+`, `CLOSED != M-`, similarity != semantic equivalence, AST symbols != reusable behavior, stack-parent metadata != semantic dependency proof, and arena winner != generalization.
10. Keep LLMT views on one canonical memory substrate; multiple views/models are not independent evidence.
11. Never infer GitHub write authority from generation scope. Writes, merges, publication and irreversible actions remain separately authorized.
12. After evidence exists, emit a `ReuseOutcomeReceipt` so useful failures/successes feed M-/M+/M? instead of being forgotten.
13. Preserve the frozen retrieval baseline under `benchmarks/omega_pr_retrieval_arena_v02_baseline.json`. Do not tune ranking weights on those baseline cases; accumulate future eligible PRs as untouched prospective cases before promotion.
