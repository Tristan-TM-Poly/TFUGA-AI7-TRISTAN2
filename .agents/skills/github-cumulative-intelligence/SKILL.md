# GitHub Cumulative Intelligence

Use this skill before proposing or drafting a new PR in this stack.

1. Refresh canonical `GitHubMemoryIndex` snapshots with the existing #447 `state=all` snapshotter.
2. Include every relevant repository index. Do not discard merged or closed-not-merged PRs.
3. Compile `omega_capability_os_t.github_cumulative_intelligence_cli`.
4. Read the minimal reuse coalition, relevant PR genomes, lineage neighborhood and negative-memory hits.
5. Progressively inspect exact candidate heads/files/tests before reusing implementation.
6. Reuse/compose/extend before creating. Create only declared residual outputs.
7. Keep provenance to repository, PR and exact head SHA.
8. Treat `MERGED != M+`, `CLOSED != M-`, similarity != semantic equivalence, and AST symbols != reusable behavior.
9. Keep LLMT views on one canonical memory substrate; multiple views/models are not independent evidence.
10. Never infer GitHub write authority from generation scope. Writes, merges, publication and irreversible actions remain separately authorized.
11. After evidence exists, emit a `ReuseOutcomeReceipt` so useful failures/successes feed M-/M+/M? instead of being forgotten.
