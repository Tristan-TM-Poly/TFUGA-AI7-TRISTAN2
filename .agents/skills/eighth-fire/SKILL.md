# Ω-8F Self-Hosting Regenerative OS

Use this skill after the intent is understood and before calling a project, product, course, capability or institution an Eighth-Fire success.

## Procedure

1. Name the beneficiaries explicitly; never infer that the system itself is the beneficiary.
2. State the capability to be left behind in observable terms.
3. Separate declared capability, executed capability and measured beneficiary capability.
4. Freeze the seven hard gates before aggregate scoring: evidence, safety, non-domination, attribution/consent, regeneration, beneficiary autonomy, rollback/contestability.
5. If a hard gate fails or is missing, return `HOLD`; suppress aggregate scoring.
6. Run anti-capture review for dependency, low exit control, missing provenance, missing falsifiers, missing exit and missing rollback.
7. If gates pass but anti-capture residue remains, return `REVIEW`, not success.
8. Run the n+1 probe set even when the design appears complete.
9. Prefer the smallest supplied structure with sufficient verified capability gain; do not create an institution merely because one can be generated.
10. Use Capability OS for actual tool routing and side-effect authority. Eighth Fire does not grant execution authority.
11. Convert Capability OS contracts to FirePackets only as declarations; do not upgrade them to measured evidence.
12. Measure capability left behind after system withdrawal when feasible.
13. Record dependency, capture exposure and irreversible harm explicitly in WorldState comparisons.
14. Require beneficiary export/exit/contestability where technically and legally feasible.
15. Treat cultural attribution as a hard boundary: this architecture is Tristan's personal system and must not be represented as authoritative Indigenous teaching.

## n+1 mandatory attacks

```text
omitted beneficiary
hidden persistent dependency
simpler comparable intervention
metric Goodhart attack
externalized cost or harm
practical revocation test
vanishing-system test
lower-capture decentralized alternative
```

## Never infer

- more automation => more benefit;
- more users => more capability;
- retention => autonomy;
- open source => consent or safety;
- revenue => distributed capability;
- gate PASS => moral truth;
- `ELIGIBLE` => permission to execute;
- Capability OS declaration => successful execution;
- successful execution => beneficiary capability gain;
- one benchmark => universal transfer;
- absence of detected capture => absence of capture.
