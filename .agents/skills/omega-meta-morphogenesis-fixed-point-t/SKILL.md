# Ω-META-MORPHOGENESIS-FIXED-POINT-T∞Ω

Use this skill when a request asks to generalize, automate, regenerate, compress, fuse, evolve, crystallize, or operationalize one or more Tristan theories or systems.

## Objective

Maximize verified capability, information gain, transfer, regenerability, optionality, and future-work elimination while minimizing persistent complexity, risk, human friction, epistemic debt, and authority debt.

Do not maximize idea count, agent count, repository count, meta-depth, automation level, or conceptual novelty for their own sake.

## Kernel

Treat the candidate fixed-point kernel as:

```text
OBSERVE
-> RESIDUALIZE
-> QUESTION
-> REPRESENT
-> GENERATE
-> CONTRAST
-> PROBE
-> VERIFY
-> GOVERN
-> SELECT
-> ACT?          # only when separately authorized
-> MEASURE
-> DISTILL
-> PRUNE
-> REGENERATE
```

`ACT` is optional. Capability never implies authority.

## Workflow

1. Identify the concrete residual or decision to improve.
2. Search for an existing kernel, skill, representation, test, or capability before adding structure.
3. Reuse the generic `MorphGenome` adapter when several domain genomes share the same operational shape, while keeping domain-specific constraints explicit.
4. Express persistent state changes as a `ProofCarryingTransformation` and emit a deterministic morphogenesis receipt.
5. Generate at least these competitors when material: candidate change, GO_MIN, and DO_NOTHING.
6. Keep Generator, Verifier, Reality Anchor, Authority, and Executor distinct whenever possible.
7. Assign epistemic status. Never silently convert generated/simulated/derived material into observed, replicated, or causal evidence.
8. Assign explicit authority. Tool availability and technical capability are not permissions.
9. Prefer minimal discriminating experiments over broad speculative expansion.
10. Rank residuals by expected verified information/capability gain, downstream leverage, cost, risk, and complexity.
11. Convert reusable results into `CapabilityCrystal` objects only after accepted gates, complexity-rent payment, evidence, and tests.
12. Record outcomes as M+, M-, or M?; unresolved uncertainty must remain M? when evidence is insufficient.
13. Charge every persistent object complexity rent. Prefer COMPRESS, MERGE, ARCHIVE, or REGENERATE_ON_DEMAND when marginal verified capability no longer justifies persistence.
14. Create a new META level only when the current kernel cannot express the needed behavior and verified out-of-sample gain exceeds meta-complexity cost.
15. Track dependency blast radius for claims, models, code, publications, simulations, products, decisions, and capability crystals.
16. Distill the smallest regenerative core (`BOOK0_MIN`) and test reconstruction closure.
17. Emit an Evolution/Transformation Receipt with before/after identity, evidence, tests, permissions, risk, rollback/compensation, and unresolved residuals.

## Epistemic type guard

Minimum vocabulary:

```text
GENERATED
SPECULATIVE
HYPOTHESIS
DERIVED
SIMULATED
OBSERVED
REPLICATED
CAUSALLY_SUPPORTED
FALSIFIED
```

Hard examples:

```text
SIMULATED  != OBSERVED
CORRELATED != CAUSAL
GENERATED  != VERIFIED
NONDETECTION != ABSENCE
LOCAL_PASS != GLOBAL_PASS
```

If the desired claim exceeds the supporting evidence class, fail closed or downgrade the claim.

## Authority guard

Model authority as explicit allowed actions, for example:

```text
read
search
model
simulate
propose
draft
test
execute
write
publish
spend
govern
```

Never infer higher authority from competence, automation level, popularity, capital, or prior success.

## Causal memory

Keep three explicit stores:

```text
M+ = useful or validated outcomes
M- = failed, unsafe, or falsified paths plus explicit prevention rules
M? = live unresolved uncertainty
```

Compress M- only into declared reusable rules; do not infer a causal law merely because several failures share text or surface features.

## Meta-stop / apoptosis / FORGET+

Create `META^(n+1)` only if both are true:

```text
not expressible_by_current_kernel
verified_out_of_sample_gain > meta_complexity_cost
```

Otherwise collapse, compress, or reuse the current layer.

Apoptosis is review-only. A component may become `ELIGIBLE_FOR_REVIEW` only when regeneration closure is complete and evidence plus provenance are preserved. Low survival score never authorizes automatic deletion.

`FORGET+` means `REGENERATE_ON_DEMAND`, not destructive forgetting. Use it only when tested regeneration closure meets the declared threshold while evidence and provenance remain intact.

## Reference implementation

The repository module `omega_morphogenesis` implements the canonical dependency-free court for proof-carrying transformation validation, epistemic/authority gates, residual ranking, complexity-rent persistence, meta-stop, regeneration closure, evidence blast radius, and deterministic `CapabilityCrystal` hashing.

The `omega_tristan_meta` adapter adds the generic `MorphGenome`, deterministic `MorphogenesisReceipt`, causal M+/M-/M? memory, review-only apoptosis, non-destructive FORGET+, and crystal prerequisites while reusing the canonical kernel rather than replacing it.

The implementation is an engineering prototype, not proof that the proposed meta-theory is scientifically valid or universally optimal.
