# PR Fractal Generation

Use this skill when a pull request should be expanded through Ω-PR-5K2N-T∞ while preserving reuse-first, cumulative memory, OAK, CVCD, M+/M-/M? and bounded physical execution.

## Core law

```text
C_n = 5000 * 2^n
```

`C_n` is a logical candidate population. It is never interpreted as a requirement to create that many files, lines, commits, agents, API calls or patches.

## R0.2 procedure

1. Resolve the exact target PR, repository and head SHA.
2. Compile or load the canonical cumulative GitHub memory and PR Genome.
3. Search historical PRs, modules, symbols, Capability contracts and M− before creating anything new.
4. Compile the #450 cumulative-intelligence capsule: Minimal Reuse Coalition, residual courts, exact inspection refs and memory lenses.
5. Resolve the structural action before generation:
   - `REUSE` when one explicit capability contract covers the requested outputs;
   - `COMPOSE` when multiple explicit contracts are needed;
   - `EXTEND` when selected capabilities cover part of the request and explicit residual outputs remain;
   - `CREATE_RESIDUAL` only when no selected capability covers the declared residual;
   - `INSPECT` fail-closed when exact inspection is required or the state is structurally ambiguous.
6. Compute the exact logical cardinality for the requested generation without enumerating the population.
7. Compile a bounded deterministic sample of virtual AddAtoms.
8. Preserve Explorer and Prosecutor alternatives for construction and falsification.
9. Deduplicate sampled patterns with CVCD-style signatures.
10. Re-rank as planning evidence using the structural decision, reuse coverage, explicit M− and evidence-bearing reuse outcomes.
11. Never use historical outcome adjustment unless the action has both `n > 0` and explicit evidence refs.
12. Search bounded complementary pairs such as code+test, reuse+test, contract+OAK and simplify+test; keep `causal_synergy_proven=false` until measured.
13. Compile only bounded `PhysicalPatchContract` objects, not source code.
14. Require source/lineage refs, exact inspection refs, tests, evidence and rollback in every physical contract.
15. Keep physical contracts at `REVIEW_CONTRACT_ONLY` with write/commit/merge authority false.
16. If the structural action is `INSPECT`, emit zero physical contracts even when generated candidates have high proxy scores.
17. If a later separately authorized renderer produces real edits, inspect the exact diff, run tests/baselines/OAK, and attach exact-head evidence before any PR mutation.
18. If a surviving physical patch set becomes large, split it into dependency-aware stacked child PRs rather than one giant diff.
19. Feed measured accepted/rejected outcomes back into M+, M− or M? so later generations learn from evidence.

## Adaptive depth

There is no fixed architectural `N_max`.

A finite execution uses explicit runtime, candidate, contract, review and compute budgets. Continue to `n+1` only when the bounded evidence still justifies another generation **and** the structural decision is not `INSPECT`. A stopped run may resume later from its recorded `next_generation_candidate`.

```text
no fixed architectural N_max != infinite physical compute
finite contract budget != architectural N_max
```

## Physicalization boundary

R0.2 may emit:

```text
PhysicalPatchContract
```

but not an automatically applied patch.

Permanent R0.2 authority state:

```text
code_change_generated = false
write_authority_granted = false
automatic_commit_allowed = false
automatic_merge_allowed = false
human_review_required = true
rollback_required = true
```

A future patch renderer requires separate explicit write authorization and exact-head validation.

## Hard boundaries

```text
5K*2^n logical candidates != 5K*2^n files or lines
logical addressability != execution
generated candidate != useful change
cumulative memory != semantic equivalence
reuse outcome history != causal proof
M+ != universal success
M- != universal impossibility
proxy score != measured engineering value
sample support != population frequency
synergy proxy != causal synergy
reuse similarity != implementation compatibility
PhysicalPatchContract != generated code
many additions != progress
CI green != external truth
```

## Authority

Default runtime authority is read + draft. Never infer commit, merge, auto-merge, publication, deployment, force-push, permission widening or irreversible authority from generation scale, historical memory or CI. Repository writes remain separately authorized and reviewable.
