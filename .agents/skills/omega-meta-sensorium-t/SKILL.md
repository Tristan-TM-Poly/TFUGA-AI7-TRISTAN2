# Ω Meta Sensorium T

## Purpose

Transform a scientific question into the smallest justified observation capability, while preserving calibration, provenance, falsifiability, independent verification, resource constraints and explicit authority boundaries.

## Mandatory distinctions

- Instrument != Evidence.
- Generated design != Physically realizable hardware.
- Simulation != Observation.
- Fit != Explanation.
- Agreement != Independent verification.
- More sensors != Better science.
- More data != More information.
- Capability != Authority.
- Generator != Judge.
- ClaimScope <= EvidenceScope.

## Search-before-build doctrine

Always attempt in this order:

`ARCHIVE/EXISTING DATA -> EXISTING INSTRUMENT -> FEDERATE/COMPOSE -> SOFTWARE/CALIBRATION UPGRADE -> MODIFY -> NEW HARDWARE RESIDUAL`

Include GO_MIN and NO_ACTION as explicit candidates.

## Workflow

1. OBSERVE the current evidence and unresolved residual.
2. FORMULATE the question and competing hypotheses/countermodels.
3. COMPILE discriminating observables and required thresholds.
4. SEARCH existing capabilities before inventing hardware.
5. GENERATE bounded observation candidates, including NO_ACTION.
6. COMPILE the Minimum Sufficient Observatory / Minimal Witness.
7. COUNTERGENERATE failure modes, artifacts, known-physics explanations and AntiDiscovery cases.
8. SIMULATE candidates only within clearly labeled model assumptions.
9. ABLATE sensors, bands, platforms, algorithms and meta-layers to test necessity.
10. VERIFY calibration, raw-data provenance, uncertainty, pipeline identity and independent judge roles.
11. EXECUTE only actions inside explicit permissions/authority; otherwise output a proposal.
12. RECEIPT observations and persistent transformations.
13. UPDATE M+ / M- / M? and unresolved blind spots.
14. REGENERATE from Observatory BOOK0 when useful.
15. META-STOP when the current kernel already expresses the needed capability.

## Minimum Sufficient Observatory

Prefer the least total resource cost that satisfies the required observables and thresholds. Do not equate fewer devices with lower cost. Include opportunity cost, risk, calibration burden, complexity and epistemic debt when the data supports them.

## Observation value heuristic

A candidate may be ranked using calibrated information value divided by resource/risk/complexity/debt, but a scalar score never overrides hard scientific, safety, calibration, legal or authority gates.

## AntiDiscovery

For every surprising signal, generate and test at least:

- instrument artifact;
- calibration failure;
- pipeline/software failure;
- background/selection effect;
- known-physics explanation;
- competing scientific model.

Do not promote `new physics` merely because the signal is surprising.

## Automation gradient

A0 manual analysis; A1 recommendations; A2 human-approved execution; A3 bounded sandbox automation; A4 zero-touch only inside an explicit verified envelope. Scientific truth claims remain subject to independent evidence and review at every level.

## Regeneration

Store only the smallest sufficient Genome + Generator + Evidence + Tests + Provenance required to rebuild the verified capability. If a smaller representation preserves frozen tests and behavior, prune the larger one.

## Output

Return the minimum useful combination of question/hypotheses, observables, capability search, candidate architectures, Minimal Witness, GO_MIN/NO_ACTION comparison, failure/AntiDiscovery analysis, calibration/evidence requirements, OAK verdict, M+/M-/M? delta, residuals, BOOK0 delta and any blocked permissions.
