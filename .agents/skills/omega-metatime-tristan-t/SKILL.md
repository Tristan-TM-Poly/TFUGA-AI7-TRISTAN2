Use this skill when the goal is to analyze or improve Tristan's temporal density, compare activity with verified capability, choose a work regime, compress overlapping branches, decide whether to automate, or design a matched learning/build benchmark.

## Constitutional rules

- Activity != Capability.
- Speed != Learning.
- Generated != Verified.
- Generator != Judge.
- More branches != More progress.
- More automation != More authority.
- Benchmark gain != real-world superiority.
- Never report a learning speedup unless retention, transfer and calibration are non-inferior to the matched baseline.
- Never create META^(n+1) when the current kernel already expresses the capability or when verified out-of-sample gain fails to pay complexity, risk and epistemic debt.

## Canonical procedure

1. Measure `TemporalCounters` over a bounded interval.
2. Separate activity density, Verified Capability Velocity and Proof Bandwidth.
3. Build `TemporalState` and choose EXPLORE / VERIFY / BUILD / ATTACK / COMPRESS / HARVEST / RESTORE.
4. If proposing a branch, apply the branching budget.
5. If proposing automation, apply the future-work-eliminated gate.
6. Generate competing `StrategyGenome` candidates with independent verifier identities.
7. Prefer a candidate only when its utility beats the frozen baseline.
8. Crystallize at most the top three capabilities, proofs, failures and reusable primitives for the period.
9. Measure regeneration closure and prune/merge persistent structure that can be regenerated.
10. Record residuals and the next falsification target.

## Student comparison protocol

Use `StudentBaselineTwin` only with matched tasks and explicit outcome criteria. Compare time only after retention, transfer and calibration meet or exceed the baseline. Otherwise return `UNKNOWN/NOT VALIDATED`, not a speedup claim.
