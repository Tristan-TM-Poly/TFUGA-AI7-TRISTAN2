# Maximum Problem Resolution Atlas R0.4

The strongest way to solve more problems is not to repeat one solver. It is to maintain a portfolio of complementary mechanisms and route each failure into the next experiment.

## Priority order

1. **Preserve counterexamples.** A failed strategy becomes a reusable regression asset.
2. **Use exact fallback before claiming failure of the problem.** Failure of one heuristic is not failure of the portfolio.
3. **Keep unresolved items visible.** A restricted one-attempt campaign intentionally demonstrates that unresolved problems remain when fallback is removed.
4. **Measure attempts per solve.** Raw solve count hides brittle or expensive strategies.
5. **Rank families by fallback dependence.** Families needing frequent fallback deserve new strategies, stronger properties or better decomposition.
6. **Expand distributions, not just seed counts.** A billion similar instances can teach less than one adversarial distribution shift.
7. **Separate fixture resolution from proof.** Finite oracle agreement is evidence, not universal correctness.

## Next expansion dimensions

- new problem families and inverse problems;
- multiple independent exact solvers;
- Python, Rust, C++, Java, Go and JavaScript runners;
- property and metamorphic generators;
- counterexample minimization;
- symbolic constraints and SMT where suitable;
- time, memory and energy budgets;
- public benchmark adapters that preserve license and provenance;
- open-problem research mode with strict hypothesis/proof separation.
