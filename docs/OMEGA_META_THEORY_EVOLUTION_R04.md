# Ω-META-THEORY-EVOLUTION-COMPILER-T∞ — R0.4

## Purpose

R0.4 crystallizes the current Tristan meta-theory work into a bounded, executable layer for **developing the development of theories**.

The primitive is not a theory object. It is a verified transformation candidate:

```text
(State, Residual, Goal, Evidence, Constraints)
    -> CandidateTransformations
    -> Attack / Benchmark
    -> Pareto Court
    -> SELECT | HOLD | IDENTITY
```

This is deliberately smaller than introducing another ontology. It reuses `omega_generative_closure_t` and its existing OAK/Pareto contracts.

## Meta-generalization

Any theory evolution step is represented as a transformation whose useful dimensions include:

- verified gain;
- evidence;
- reuse and regenerability;
- interoperability / transferability;
- cost and risk;
- proof / semantic / structural debt;
- uncertainty and irreversibility.

A theory, experiment, simulation, document, code patch, publication or product can therefore be compared through a common transformation envelope without claiming that those objects are semantically identical.

## Meta-generation

The target loop is:


## Meta-automation

Automation is itself a candidate transformation, not an automatic good.

```text
Repeated Manual Pattern
-> Automation Candidate
-> Sandbox / Tests
-> Evidence Receipt
-> Cost + Risk + Maintenance
-> PROMOTE | HOLD | REJECT
```

The system should optimize future work eliminated per unit of attention, compute, risk, debt and persistent complexity rather than raw automation count.

## R0.4 regeneration benchmark

`regeneration_benchmark(...)` performs the next experiment explicitly requested by R0.3:

1. compute the full declared closure;
2. find a cardinality-minimal seed basis inside the declared finite seed universe;
3. regenerate the declared observables;
4. measure retained-observable ratio and closure reconstruction ratio;
5. measure finite subset-search cost;
6. measure cost of fired rules;
7. track evidence debt against a declared floor;
8. ablate each retained basis seed and record lost observables;
9. verify second-pass stability.

The benchmark produces `PASS` only for the declared structural gates. It does **not** establish scientific truth, semantic equivalence, universal optimality or a physical renormalization fixed point.

## Selection court: no fabricated winner

`select_next_transformation(...)` reuses the existing Pareto frontier.

Rules:

- one unique Pareto survivor -> selected;
- multiple incomparable/tied survivors -> `HOLD`;
- zero candidates -> `IDENTITY` / `DO NOTHING`;
- scalar power density is not used to break a tie.

This implements the OAK rule that an equality or representational tie must not manufacture a winner.

## 2^n -> n+1 ladder

The artifact workflow is encoded as a falsification ladder:

```text
capacity(n) = 2^n
probe(n)    = 2^(n+1)
```

Reaching level `n` is never treated as proof of saturation. The next level is always exposed as an explicit probe. The `power_ladder_step(n)` receipt records both current capacity and the mandatory `n+1` probe.

This does **not** mean materializing exponentially many files. Under GO MIN, the ladder measures capability coverage and evidence-bearing surfaces; virtual/regenerable artifacts are preferred when equivalent.

## Anti-add law

Before creating a new persistent system:

```text
SEARCH -> REUSE -> COMPOSE -> GENERALIZE -> COMPRESS -> CREATE_RESIDUAL
```

A new layer survives only if:

```text
VerifiedCapabilityGain > PersistentComplexity + EvidenceDebt + MaintenanceDebt
```

Otherwise reuse, HOLD, fission, archive or apoptosis is preferred.

## Theory population and speciation

Future work may maintain several theory descendants when the Pareto court cannot establish dominance. Fusion is justified only by measured complementarity; specialization/fission is preferred when coordination cost and interference exceed verified synergy.

`Popular != Correct` and `Merged != True` remain hard boundaries.

## Residual gradient and Hessian — status

The chat-derived concepts of a theory residual gradient and residual Hessian are retained as **research hypotheses**:

- gradient: estimate which discrete transformation most reduces declared residual mass;
- Hessian-like coupling: estimate interaction among transformation pairs.

These names are analogical until an explicit metric, probe family, finite-difference construction and sensitivity analysis are implemented. They are not mathematical gradients/Hessians by declaration.

## Regime controller — target, not yet promoted

Candidate operational regimes remain:

```text

```

A future controller should choose among them using measured bottlenecks such as residual pressure, proof backlog, harvest debt, complexity budget and epistemic ROI. R0.4 intentionally does not encode arbitrary thresholds yet.

After R0.4 exact-head CI, the next useful probe is not another vocabulary layer. It is a **cross-context regeneration benchmark**:
