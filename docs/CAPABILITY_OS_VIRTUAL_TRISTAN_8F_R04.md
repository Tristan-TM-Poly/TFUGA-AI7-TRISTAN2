# Capability OS Virtual Tristan — Eighth Fire R0.4

R0.4 absorbs the useful constitutional and proof-of-transfer ideas from the broader Eighth-Fire runtime into the already-canonical Capability OS beneficiary-flow court. It intentionally does **not** create another capability or agent ontology.

## Compression

```text
Intent
-> Capability OS
-> optional Virtual Tristan / minimum sufficient swarm
-> beneficiary-flow court
-> constitutional gates
-> prospective proof-of-transfer
-> OAK + real authority
-> HOLD | PASS
```

`PASS != PermissionToExecute`.

## Constitutional gates

R0.3 already treated consent, attribution, dependency, capture, harm, autonomy, reciprocity and dependency half-life as non-compensatory beneficiary-flow constraints.

R0.4 adds an explicit constitutional projection for:

1. evidence
2. safety
3. non-domination
4. regeneration
5. rollback/contestability

These gates are supplied explicitly to `evaluate_constitutional_beneficiary_flow`. They are not inferred from the diagnostic score and cannot be compensated by a high score.

## Prospective proof-of-transfer

A real beneficiary-capability claim should be tested against frozen criteria:

```text
baseline capability
-> assisted capability
-> system withdrawal
-> independent task
-> delayed replay
-> post-withdrawal dependency
-> frozen evaluator
-> TransferEvidenceReceipt
```

`FrozenTransferCriteria.digest()` freezes the criteria before observation. A later metric or threshold mutation creates `criteria_digest_mismatch` and forces HOLD.

The court also holds when generator and evaluator collapse into one identity where separation is required, when the system was still available during the claimed withdrawal test, when post-withdrawal dependency exceeds the frozen limit, when retention is insufficient, or when delayed capability fails to exceed baseline when that criterion is enabled.

## What the receipt does not prove

- finite PASS != randomized causal effect
- evaluator identity separation != statistical independence
- delayed replay != lifetime empowerment
- declared system withdrawal != proof of zero hidden support
- one beneficiary != complete beneficiary discovery
- PASS-Québec != validation outside Québec
- GatePASS != moral truth
- technical court != cultural authority

## Québec-first experimental profile

The intended first real-world profile is a bounded Québec pilot with pre-registered criteria and named beneficiaries. A candidate pilot should freeze at minimum:

- beneficiary set;
- baseline task(s);
- capability observable(s);
- evaluator identity/provenance;
- withdrawal condition;
- delayed replay condition;
- dependency ceiling;
- rollback and stop conditions.

A PASS can only justify further controlled testing. It cannot authorize geographic expansion by itself.

## Cultural boundary

The Eighth-Fire architecture in this repository is Tristan's personal normative/engineering construction. It must not be represented as authoritative Indigenous doctrine, as speaking for Anishinaabe peoples, or as proving an interpretation of their teachings.

## Anti-inflation / ablation law

Before creating a new Eighth-Fire runtime, agent or named architecture, attempt to encode the need as an existing Capability OS role, probe, gate, receipt, metric or profile.

```text
SEARCH -> REUSE -> COMPOSE -> EXTEND -> CREATE
```

If an abstraction can be removed without reducing verified capability, evidence quality, authority separation or falsifiable behavior, it should remain an alias/profile or be pruned.

## Next reality benchmark

The next meaningful n+1 is not R0.5 by default. It is a pre-registered prospective Québec transfer pilot that produces observations from the real world. Until such evidence exists, R0.4 validates deterministic software behavior and a falsifiable protocol, not beneficiary impact.
