# Capability OS / Eighth-Fire Social Legitimacy R0.5

## Purpose

R0.5 does **not** optimize social acceptance. It evaluates whether a proposed deployment creates the conditions for an informed, voluntary, contestable and reversible decision.

Core invariant:

`Acceptance != Objective`

Preferred chain:

`Need -> Proposal -> Evidence -> Understanding -> Agency -> Choice -> Experience -> Capability -> Autonomy`

A valid choice may be `YES`, `NO`, `REVISE`, or `NO_ACTION`.

## Canonical placement

This is a Capability OS / Eighth-Fire **profile/court**, not a new OS, agent population, ontology or persuasion runtime.

`Capability OS -> Eighth-Fire constitutional gates -> social_legitimacy_profile -> OAK/real authority`

## Hard invariants

- `AcceptanceRate↑ != SocialLegitimacy↑`
- `Consensus != Truth`
- `ClickedAccept != InformedConsent`
- `Consent(v1) != Consent(v2)` after material change
- `LegitimateProcessPASS != AdoptionPASS`
- `EvidenceOfBenefit != AuthorityToDeploy`
- `PersonalizedManipulation -> DENY`
- `MinorityResidual != NoiseToErase`

The acceptance rate is recorded for analysis but is never a positive gate. A process with 0% adoption can PASS if people understood the proposal and freely rejected it.

## Frozen legitimacy criteria

Before observing outcomes, freeze:

- initiative identifier;
- system version;
- consent version;
- evaluator identity;
- minimum understanding;
- minimum agency;
- maximum acceptance debt;
- opt-out requirement;
- contestability requirement;
- reversibility requirement;
- evidence-transparency requirement;
- stakeholder-representation requirement;
- evaluator-separation requirement;
- personalized-manipulation prohibition.

The criteria digest makes post-observation metric mutation detectable.

## Acceptance Debt

R0.5 operationalizes a bounded diagnostic quantity:

`AcceptanceDebt = unresolved_concerns + information_asymmetry + hidden_dependency + unmeasured_harm + unrepresented_stakeholders`

This is not a moral score. It is a falsifiable engineering indicator intended to block the claim that high adoption compensates for unresolved legitimacy debt.

## Versioned consent and reconsultation

A material system change invalidates silent reuse of prior consent.

`SystemDiff -> ImpactDiff -> ConsentImpact -> RECONSULT when material`

R0.5 HOLDs when `material_change_since_consent=True`, or when the observed system/consent version differs from the frozen criteria.

## Minority residual preservation

Disagreement is evidence, not garbage. Important minority objections remain visible as residuals even when a deployment decision proceeds.

The court blocks an observation that declares minority residuals and then erases them from the evidence surface.

## Anti-persuasion boundary

Allowed:

- accessibility adaptation;
- language translation;
- role-appropriate explanation;
- alternative representations pointing to the same claims/evidence.

Denied:

- psychological-vulnerability targeting;
- individualized manipulation to raise acceptance;
- hiding alternatives or burdens to improve conversion;
- redefining success after observing responses.

## Québec-first application profile

For a real Québec pilot, preregister at minimum:

1. affected and beneficiary groups;
2. baseline / no-deployment alternative;
3. evidence and uncertainty to disclose;
4. understanding and agency measures;
5. opt-out, contestation, rollback and exit mechanisms;
6. minority-residual handling;
7. acceptance-debt components;
8. material-change/reconsultation rule;
9. evaluator/provenance separation;
10. PASS / HOLD / REVISE / NO_ACTION criteria.

The goal is **not** “make Québec accept the system.” The goal is to increase Québec's verified capacity to understand, test, modify, adopt or refuse systems that affect it.

## OAK nonclaims

A software PASS proves only that the supplied observation satisfies the frozen finite criteria implemented by the court. It does not prove moral correctness, genuine representativeness, causal benefit, legal compliance, Indigenous cultural authority, absence of unknown harms, or permission to deploy.

## n+1 attacks

Every apparent PASS should generate at least one adversarial pass for:

- forgotten stakeholder;
- hidden dependency;
- information asymmetry;
- cheaper / less intrusive alternative;
- externalized harm;
- consent invalidated by version change;
- minority concern hidden by averages;
- evaluator/generator collusion;
- Goodhart optimization of acceptance rate;
- inability to leave after adoption.

The next epistemically meaningful step after R0.5 is a preregistered, bounded Québec legitimacy/transfer pilot with real participants and real withdrawal/choice evidence, not another automatic vocabulary layer.
