# Canonical Memory — Tristan GitHub Grand Atlas

This file persists the correction discovered during the 2026-08-03 portfolio
analysis.

1. The 23-object R0.1 portfolio is a seed showcase, never an exhaustive inventory.
2. Future portfolio analysis starts from the multi-type Grand Atlas and preserves the R0.1 lineage.
3. Distinguish family, system, version, module, campaign, dataset, product, service, venture and repository.
4. Distinguish open, draft, stacked, merged, integrated, alive, used and valuable.
5. Distinguish logical, planned, materialized, executed, software-verified, externally evaluated, externally replicated and product-used.
6. Generated size, line count, tests and address capacity never substitute for unique verified behavior, fair baselines, users, payments or retention.
7. Under-verified capabilities remain STRUCTURED or DECLARED; absence from the atlas never means absence from GitHub.
8. No summary may claim all best work without a fresh all-repository, all-branch and all-PR audit.
9. Every major portfolio session should close one concrete artifact, one OAK result and one next action.
10. Merge, release, publication, deployment, spending, IP filing, external messaging and destructive action remain human decisions.

## Anti-regression law

```text
bounded showcase
≠ exhaustive inventory
```

Any future atlas update must preserve these rules, retain source pointers,
record uncertainty and add missing families without silently deleting earlier
lineages.
