# Ω‑META‑AXIOME‑TRISTAN‑T∞Ω — R0.1

## Mission

Transform **Axiome‑Tristan.com** from a library of ideas into a proof-carrying knowledge laboratory where an important statement can be typed, scoped, attacked, tested, versioned, bounded, remembered, and regenerated.

R0.1 is an engineering scaffold. It is **not** evidence that the architecture is scientifically superior, commercially valuable, or generally optimal.

## Canonical pipeline

`CLAIM → CLAIM PASSPORT → OAK TYPE/SCOPE COURT → ADVERSARIAL MUTATIONS → DISCRIMINATING PREDICTIONS → M− → BOOK0 REGENERATION`

## Core objects

- `ClaimPassport`: statement, kind, domain, definitions, scope, assumptions, dependencies, evidence, counterevidence, uncertainty, falsifiers/proof obligations, provenance, status, and version.
- `AxiomGenome`: a ClaimPassport plus consequences, predictions, tests, boundary conditions, lineage, and mutation metadata.
- `OAKReport`: non-compensatory gate results and a deterministic report digest.
- `NegativeMemoryEntry`: executable M− record compiled from failed gates.
- `Book0Manifest`: candidate minimal regenerative basis and probe family.

## Hard invariants

```text
Generated != Verified
Formalized != True
Simulation != Reality
Generator != Judge
ClaimScope <= EvidenceScope
Revenue != Truth
Capability != Authority
LocalPASS != GlobalPASS
```

No aggregate score can compensate for a failed hard gate.

## Axiom Arena

R0.1 generates bounded adversarial candidates:

- `NEGATE`
- `NARROW_SCOPE`
- `BOUNDARY_HUNT`

These candidates are explicitly non-authoritative. A heuristic support score may be used for triage only; it is never a truth score or promotion authority.

`discriminating_predictions(left, right)` identifies prediction pairs that use the same variable and condition but expect different outcomes. The resulting experiment key is a research pointer, not permission to run a real-world experiment.

## Claim-scope court

Once a claim reaches `TESTED` or a stronger status, every declared scope dimension must be covered by supporting evidence metadata. If evidence covers only a local regime, the claim must remain local or be weakened.

The court also blocks:

- empirical corroboration based only on simulation/derivation;
- `REPLICATED` without independent replication evidence;
- `FORMALLY_VERIFIED` without formal-proof evidence and a compatible formal claim type;
- generator/judge identity collapse;
- strong promotion that silently ignores declared counterevidence.

## Status boundary

The status vocabulary is intentionally typed:

`IDEA → CONJECTURE → FORMALIZED → TESTABLE → TESTED → CORROBORATED / REPLICATED`

Formal mathematics may instead reach `FORMALLY_VERIFIED` when a compatible formal claim is backed by formal-proof evidence. `REFUTED` and `BOUNDED` remain first-class outcomes.

Scientific claims are not treated as mathematical theorems merely because they are formalized.

## R0.2 falsifiable frontier

R0.2 must be earned by measured gain over simpler baselines. Priority comparisons:

1. ordinary review checklist vs structured ClaimPassport;
2. baseline critique vs adversarial mutation court;
3. text-only provenance vs claim-lineage graph;
4. static BOOK0 snapshot vs held-out regeneration tasks;
5. single evaluator vs generator/judge separation;
6. local structural OAK results vs independent human review calibration.

A new META layer is justified only when out-of-sample verified gain exceeds added complexity, compute, risk, human friction, and epistemic debt.
