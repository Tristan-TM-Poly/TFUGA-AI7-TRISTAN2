# Ω-AIT-LLMT-ALLT-META-MORPHOGENESIS-T∞Ω — R0.1

## Status

Engineering hypothesis and executable research scaffold. This document does **not** claim a scientific law, autonomous general intelligence, self-reproduction, or proven superiority over static agent systems.

## Core claim to test

For some task classes, dynamically compiling the smallest sufficient cognitive organization can reduce persistent complexity and coordination cost while preserving or improving verified task performance versus fixed-agent baselines.

## Working hierarchy

`AI ⊂ AIT ⊂ LLMT ⊂ ALLT` is a useful working hierarchy, not an ontological commitment. A program, solver, simulation, graph, or hybrid may dominate an agent architecture on a given mission.

## Candidate primitives

Residual, Question, Representation, Capability, Transformation, Evidence, Uncertainty, Authority, Memory, Regeneration.

## Morphogenesis loop

`OBSERVE → RESIDUALIZE → QUESTION → REPRESENT → GENERATE → COMPOSE → EXECUTE → VERIFY → COUNTERFACTUALIZE → SELECT → DISTILL → PRUNE → REGENERATE → META-VERIFY`

All arrows are candidates for specialization, replacement, compression, or deletion when evidence supports it.

## R0.1 executable scope

The `omega_ait_llmt_allt_t` package implements only deterministic `MissionIR` validation, non-compensatory OAK hard gates, topology proposals among `NO_ACTION`, `GO_MIN`, `AIT`, `LLMT`, `ALLT`, representation heuristics, candidate genome mutation with mandatory `auto_promotion=false`, deterministic regeneration seed receipts, and JSON-schema/CI contracts. It deliberately performs no external action.

## Falsification program

Benchmark at least: single static agent; fixed multi-agent coalition; deterministic program/solver when applicable; and R0.1+ evolved JIT architecture. Measure task correctness, independent verification pass rate, latency, compute, coordination overhead, persistent complexity, failure detectability, and regeneration fidelity.

Reject or narrow the theory if JIT morphogenesis does not improve a Pareto frontier on any meaningful task class.

## Promotion requirements

A future R1 must add real executors only behind explicit tool permissions, observability, independent verification, rollback, replay, adversarial tests, and architecture receipts. No autonomous permission escalation or auto-promotion is permitted.
