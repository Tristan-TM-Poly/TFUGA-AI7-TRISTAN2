# Ω-ZETA-CERT-T∞ — Spectral Certificate & AI Mathematics Research Engine

## Mission

Turn the 2026 zeta-function experiment into an executable **research compiler**, not a headline and not an RH-claim generator.

```text
external result / theorem family

→ declared method ceiling
→ target

→ CVCD moment lift

```

## Non-negotiable OAK boundary

```text
67.25% reported != RH
formal artifact != independent mathematical review
optimized window != route above a proven/declared family ceiling
finite numerical search != theorem
fractal pattern != RH evidence
VOI score != probability of truth
```

The bundled Anthropic-2026 values are **external reported inputs**. The package does not independently reconstruct the paper or Lean development by merely storing them.

## Core object: certificate family

A certificate family records:

- current reported bound;
- declared method ceiling;
- Fourier-support budget;
- assumptions;
- epistemic status;
- source references.

The first executable question is not “is RH true?” but:

> Does a proposed target fit inside the declared information class, or does it require genuinely new arithmetic information?

## Barrier compiler

For the seeded bandwidth-one family:

- current reported bound: `0.6725`;
- declared family ceiling: `0.6818`;
- default research target: `0.70`.

Therefore `0.70` is deliberately classified as:

```text
NEW_ARITHMETIC_INFORMATION_REQUIRED
```

This prevents a generator from spending unbounded search on windows while pretending the same information class can cross its declared wall.

## CVCD spectral-moment lift

The package represents the proposed Tristan extension

```text
(M1, M2)
→ (M1, ..., MK)
→ cross moments tr(G_i G_j ...)
→ moment tensor
→ stronger constrained spectral problem
```

through `MomentTensorSpec`.

For `W` windows and symmetric cross-moments through order `K`, the compiler counts

```text
Σ_{k=1..K} C(W+k-1, k)
```

observable coordinates.

The support radius is tracked conservatively as an **upper-bound bookkeeping cost** under repeated products/convolutions. It is not itself a theorem that the required zeta correlations exist or are known.

## Effective-rank diagnostic

`effective_rank_diagnostic(trace, frobenius_sq)` computes

```text
(tr A)^2 / ||A||_F^2
```

as a generic spectral concentration diagnostic.

It is intentionally **not** labeled as a zeta theorem. A rank lower bound requires the hypotheses of the relevant mathematical inequality and a proof that the matrix/operator decomposition has the required properties.

## Four initial research routes

1. **Higher spectral moments / TensorProdLift-T**
   - derive and attack `M3, M4, ...` and cross moments;
   - compile every new observable to its exact arithmetic-information debt;
   - primary route for crossing a declared two-moment/information wall.

2. **FFWT-Weil window search**
   - parameterize Gabor/FFWT-style windows;
   - optimize only inside an explicit Fourier-support budget;
   - useful for closing remaining headroom, never for silently bypassing the ceiling.

3. **Lean semantic round-trip**
   - formalize the exact restricted statement before searching for a proof;
   - separate statement alignment from kernel acceptance;
   - reuse Ω-FORMAL-PROOF-T∞ / existing `omega_millennium_t` formal bridge.

4. **Countermodel court**
   - run candidate lemmas on analogue functions where RH-style statements can fail;
   - locate the first unjustified proof step;
   - promote failures to M− instead of discarding them.

## M− as a gradient of the proof space

A failed route is stored as a typed barrier record:

```text
route
→ first invalid step
→ barrier class
→ falsifier
→ reusable M− cell
```

The seed registry includes:

- bandwidth-one ceiling misuse;
- fractal/numerical pattern promoted beyond its evidence class.

## Bayes-Tristan / VOI

Routes are ranked by a bounded heuristic score combining:

- expected information gain;
- verification strength;
- novelty potential;
- estimated cost;
- epistemic risk.

The score is a **routing heuristic only**. It is never a posterior probability that RH is true or that a proof route will succeed.

## HGFM / Problem Atlas integration

`compile_problem_cells()` emits R0.10-compatible cells with:

- stable deterministic IDs;
- `problem_id = riemann-hypothesis`;
- fronts for barrier, representation, research route and M−;
- explicit `proof_claimed=false` / `rh_solved_claimed=false` fields.

This lets the existing streaming/Merkle/quarantine machinery scale a zeta campaign without weakening mathematical claim boundaries.
