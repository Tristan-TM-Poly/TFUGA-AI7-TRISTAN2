# Ω-CHEAT-CODE-ENGINE-T R0.1

## Status

Architecture/heuristic kernel. This is **not** a scientific theory and does not certify that an evolution is correct, optimal, safe, or profitable.

## Purpose

Crystallize the Tristan Cheat Code into a deterministic compiler primitive:

`INTENT → REFRAME/REPRESENT → CANDIDATES → EEV → META-DEPTH → OAK → PLAN → EVIDENCE → REVIEW`

The kernel intentionally stops before remote mutation or automatic merge.

## R0.1 primitives

- `EvolutionState`: desired vs verified capability plus residual, surprise, uncertainty, opportunity and evidence.
- `EvolutionCandidate`: candidate transformation with success probability, value, reuse, evidence gain, option value, compute/time cost, risk, debt, novelty and internal-closure coverage.
- `expected_evolution_value()`: ranks candidates by useful expected gain relative to explicit penalties.
- `rank_candidates()`: rejects zero-novelty candidates already reconstructible by the internal closure.
- `MetaDepthTrial` / `select_meta_depth()`: selects the meta-level with the best verified-gain density instead of defaulting to the deepest recursion.
- `lifecycle_action()`: `keep`, `distill`, or `kill` based on verified marginal gain and capability-preserving complexity reduction.
- `ProofEnvelope`: requires a claim, evidence, bounded uncertainty and rollback path.
- `compile_evolution_plan()`: emits a deterministic, proof-required plan with `automatic_merge=false`, `remote_mutations=0`, and `theorem_claimed=false`.

## GO hierarchy

The kernel is a reusable decision primitive for:

`GO PR ⊂ GO ALL PR ⊂ GO REPO ⊂ GO TRISTAN`

It does **not** copy itself blindly into every repository. GO TRISTAN should first measure interface stability, reuse value, residual reduction and repository-specific fit, then propagate only the minimal stable contract.

## Relationship to existing components

R0.1 is deliberately small and compositional:

- `omega_intent_t` remains responsible for intent/repository impact routing.
- GitHub reactor tooling remains responsible for repository audits and OAK reporting.
- CI admission remains responsible for selecting/checking validation surfaces.
- Ω-CHEAT-CODE-ENGINE-T contributes candidate ranking, adaptive meta-depth, internal-closure/novelty gating, lifecycle selection, and proof-required evolution plans.

The objective is reuse, not replacement.

```json
{
  "intent": "Improve repository evolution routing",
  "state": {
    "desired_capability": 10,
    "verified_capability": 6,
    "surprise": 1,
    "uncertainty": 1,
    "opportunity": 2,
    "evidence": 1
  },
  "candidates": [
    {
      "name": "minimal-router-improvement",
      "success_probability": 0.8,
      "value": 2,
      "reuse": 1.5,
      "evidence_gain": 1.2,
      "option_value": 1.1,
      "compute_cost": 1,
      "time_cost": 1,
      "risk": 0.5,
      "debt": 0.5,
      "verified_marginal_gain": 1
    }
  ],
  "meta_trials": [
    {"depth": 1, "verified_gain": 2, "compute_cost": 1, "risk": 0.1, "debt": 0.1}
  ]
}
```

Run:

```bash
python -m omega_cheat_code_t.cli --input plan.json --pretty
```
