# Ω-VIRTUAL-TRISTAN-MORPHOGENETIC-CIVILIZATION-T∞ — R0.1

## Purpose

A Virtual Tristan is a temporary, role-scoped projection over Capability OS. It is not a sovereign autonomous agent and it cannot gain authority merely by composition.

```text
Intent
  -> ResidualField
  -> RequiredRoles
  -> Capability OS projection
  -> VirtualTristanPopulation
  -> Generate / Attack / Verify / Compress
  -> Receipt
  -> Promote / Hold / Apoptosis
```

## Core invariants

1. `VirtualTristan != independent intelligence`.
2. `Consensus != proof`.
3. `CanDo != MayDo`.
4. `MoreTristans != MoreIntelligence`.
5. Generator, falsifier, verifier and promotion authority should remain explicitly separated.
6. A role without an authorized capability remains unresolved rather than receiving implicit authority.
7. Virtual Tristans are ephemeral by default; persistence requires measured repeated value.
8. Apoptosis is based on measured marginal contribution, not popularity or rhetorical importance.

## Canonical roles

The stable seed roles are Mycelium, Architect, Engineer, Founder and OAK. Counter-power roles include Falsifier, Reality, Historian, Compressor, Apoptosis and Collusion Detector. Domain-specific roles should be compiled only when a residual requires them.

## Capability projection

A Virtual Tristan reuses existing `Capability` fields:

- domains;
- consumes / produces;
- authority;
- information gain;
- verifiability;
- reuse;
- cost / latency / risk.

The runtime does not introduce a second capability ontology.

## Population compilation

`compile_virtual_tristans(...)` accepts:

- a Capability OS registry;
- an Intent carrying authority;
- required roles;
- an explicit role -> capability mapping;
- population and compute budgets.

It fails closed on unresolved required roles or budget overflow.

## Separation gate

```text
Generator != Falsifier != Verifier != PromotionAuthority
```

Identity separation is a governance constraint only. It does not prove statistical, source, semantic or causal independence.

## Apoptosis

A member is an apoptosis candidate when its measured marginal contribution is at or below the configured threshold. This supports minimum-sufficient swarms rather than permanent agent bureaucracies.

## OAK boundary

`READY` means only that a finite population can be compiled from supplied capabilities under declared authority and budget. It does not certify truth, intelligence, external usefulness, scientific validity, user demand or independence.

## n+1

The next meaningful step is not to add dozens of permanent Tristan roles. It is to run controlled tournaments on real tasks, record receipts, estimate marginal contribution, detect collusion/source overlap, and prune roles whose ablation does not reduce verified closure.
