# Ω-INVARIANT-OPERATOR-GENESIS-T R0.2 — Trace → ProblemHypothesis → Operator

## Mission

Move one falsifiable layer upstream from R0.1.

R0.1 required an explicit invariant set before synthesizing operator witnesses. R0.2 asks whether a small graph invariant language can recover useful constraint hypotheses from observations and then feed them into the exact oracle without hand-supplying the TSP invariants.

```text
positive graph-state traces
+ explicit feature grammar
→ candidate invariant hypotheses
→ held-out positive-trace falsification
→ ProblemHypothesis
→ R0.1 exact operator oracle
```

This is **not** autonomous discovery of mathematics from raw reality. The graph representation, node domain, positive-trace semantics and feature templates are declared inductive biases and remain visible in `GraphInvariantGrammarLedger`.

## R0.2 objects

### `GraphInvariantGrammarLedger`

Records the current hypothesis language:

- constant edge count;
- endpoint membership in a declared node domain;
- uniform node degree;
- constant connected-component count;
- persistent-edge candidates.

The persistent-edge template is intentionally useful as a falsification trap: a feature that appears invariant on a small training sample may disappear on held-out valid states.

### `InvariantHypothesis`

Each hypothesis carries:

- kind and parameter;
- training support;
- holdout support;
- status;
- human-readable description.

A hypothesis becomes `TRACE_SUPPORTED` only when support is exactly `1.0` on both training and held-out positive states. With no holdout it remains `TRAIN_SUPPORTED` and the containing problem is `HOLD`.

### `ProblemHypothesis`

Packages the trace-supported constraints but explicitly retains:

```text
objective = None
objective_authorized = false
intervention_authorized = false
theorem_claimed = false
```

Constraint induction is therefore separated from teleology and action authority.

## TSP-derived pilot without TSP invariant input

The deterministic R0.2 fixture supplies several valid 5-node cycle edge sets as training and held-out observations.

The miner recovers the following structural hypotheses from the declared grammar:

```text
edge_count_eq(5)
endpoints_in_domain
uniform_degree_eq(2)
component_count_eq(1)
```

Training-specific persistent edges are generated as candidates but rejected when unseen valid tours do not preserve them.

The surviving hypotheses are then materialized into executable predicates and sent to the exact R0.1 finite oracle. The minimal non-identity shell returns:

```text
symmetric_difference = 4
exchange_signature = (2 removed, 2 added)
```

Only after synthesis may the TSP adapter recognize that signature as the classic 2-edge-exchange / 2-opt family.

The new vertical slice is therefore:

```text
observed valid states
→ candidate constraints
→ holdout falsification
→ structural problem hypothesis
→ exact transformation witness
```

rather than:

```text
human writes TSP invariants
→ solver finds transformation
```

## Critical ablation: grammar changes the discovery

R0.2 contains a direct anti-overclaim test.

With the full grammar, the mined degree/connectivity hypotheses force the first valid non-identity shell to distance `4`.

If the grammar is ablated to only:

```text
constant_edge_count
endpoint_domain
```

then the exact oracle finds a distance-`2` transition.

Therefore:

```text
the discovered operator depends materially on the hypothesis language.
```

This is executable evidence for the doctrine:

```text
ZERO HEURISTIC -> impossible as a literal claim
ZERO HIDDEN HEURISTIC -> viable engineering target
```

The system does not hide the feature language that makes the discovery possible.

## Why no objective discovery yet

R0.2 intentionally refuses the proposed shortcut:

```text
entropy pattern -> inferred intention -> autonomous objective
```

Observed regularity does not uniquely determine a normative goal. A later objective-hypothesis layer must separate:

- observed behavior;
- candidate utility explanations;
- causal/interventional evidence;
- stakeholder or governance authorization.

For now, `ObjectiveHypothesis` is only a typed container whose default authorization is `false`.

## Relation to the larger Reality Compiler program

R0.2 is the first executable approximation to:

```text
Observation
→ InvariantGenesis
→ ProblemGenesis
→ OperatorGenesis
```

It does **not** yet implement:

- raw sensor or continuous-data segmentation;
- ontology genesis;
- representation genesis;
- arbitrary mathematical language synthesis;
- causal objective inference;
- SMT/SyGuS backend synthesis;
- hardware co-design.

Those remain research frontiers rather than implementation claims.

## OAK boundaries

```text
trace support != universal law
feature grammar != discovered mathematics
positive examples != causal explanation
ProblemHypothesis != authorized objective
constraint induction != intention discovery
minimal state delta != best optimization move
operator witness != intervention authority
held-out success != out-of-distribution generalization
```
