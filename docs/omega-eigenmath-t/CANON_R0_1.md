## Millennium lock

The six open Millennium problems are represented only as `boss_locked_unproven=True` metadata records. R0.1 rejects an internal promotion to `FORMALLY_PROVED` or `INDEPENDENTLY_VERIFIED` unless an explicit external community-acceptance receipt is attached. The project intentionally contains no candidate proof of an open Millennium problem.

Poincaré should be added later as a positive historical reconstruction benchmark, with source/proof dependency hygiene and clean-room leakage controls.

## Proof debt

Generated obligations that outrun checking capacity accumulate debt. Once a configured ceiling is reached, execution mode becomes `VERIFY_ATTACK_COMPRESS` rather than continuing unconstrained generation.

## Crystallization

Positive crystallization currently requires `INDEPENDENTLY_VERIFIED`. Failed/falsified work can crystallize as `FailureCrystal`, preserving the failure pattern, mechanism, detector, scope and provenance.

## Regeneration

R0.1 regeneration is content-addressed and tests closure over crystal digests. This is only R0 object-level closure; it is not yet clean-room rediscovery or semantic regeneration.
